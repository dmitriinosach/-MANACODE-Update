# Обмен Market Based Auction

Карточка Market Based Auction устанавливает публичный аддон обычным механизмом каталога.
Папка аддона, база `AuctionScanDB` и инбокс остались под именем AuctionScan.
Доступ к гильдейской истории настраивается отдельно, в `%APPDATA%/Manacode/AuctionMarket.json`. Адрес сервиса по умолчанию зашит в Updater (`marketDefaultURL`); поле `url` в файле его переопределяет.
Ссылка «Файл настроек обмена» создаёт файл и открывает его.

| Состояние карточки | Что видно |
|---|---|
| Нет токена | «Не подключено к базе рынка», поля логина и пароля БД (не аккаунт WoW), «Подключить»; Enter отправляет, Tab переключает поле, в поле в фокусе мигает курсор |
| Есть токен | Плашка связи: точка и заголовок по последнему ответу сервера, логин, аккаунт, время ответа или причина отказа; строки «Сканы», «История», «В игре»; «Синхронизировать сейчас», «Проверить связь», переключатель «Автообмен»; ссылка «Отключиться от базы» |

Пароль отправляется только на HTTPS login и не сохраняется; поле очищается после
отправки. Без выбранного аккаунта вход берёт аккаунт с самым свежим SavedVariables.
Успешный вход сразу запускает обмен. Полученный токен сохраняется через Windows DPAPI
для текущего пользователя. Токен не попадает в аддон, архив, URL или статус окна.

Связь проверяется `GET /v1/capabilities`: при открытой карточке — раз в минуту, плюс
каждый обмен. Результат пишется в `AuctionMarket-status.json` рядом с настройками,
поэтому окно показывает и то, что сделал фоновый `-watch`.

| Ответ | Состояние | Что делает Updater |
|---|---|---|
| 200 | подключено | — |
| нет соединения, веб-страница вместо API, 5xx | сервер не отвечает | токен остаётся, следующая попытка по расписанию |
| 401, 403 | база отклонила доступ | токен удаляется, карточка показывает вход |

| Настройка | Значение |
|---|---|
| url | HTTPS-адрес сервиса; HTTP разрешён только для localhost при тестировании/туннеле |
| protectedToken | Bearer-токен после входа, зашифрованный Windows DPAPI; вручную не менять |
| login | Запомненный логин, пароль в настройках отсутствует |
| deviceID | Постоянный случайный ID установки; с выбранным аккаунтом образует источник |
| serverID | Профиль сервера, совпадающий с серверной базой |
| realm, faction, pool | Рынок для загрузки; faction — Horde/Alliance, pool обычно faction |
| account | Имя каталога WTF/Account; выбирается кнопкой в карточке |
| days | Период скачивания: 7/30/90 дней, 0 — всё в пределах лимита клиента |
| automatic | Автообмен в открытом окне или фоновом `-watch`; по умолчанию выключен |
| done, sources | Подтверждения отправки и привязка токена к аккаунту; вручную не менять |

Чтение SavedVariables не исполняет Lua: используется существующий парсер литералов
с ограничением глубины 32. Размер файла ограничен 512 МиБ, размер и mtime сверяются
до и после чтения. Файл меняется при чтении — повторить позднее. Собственные сканы
не удаляются; общий инбокс не отправляется как новые личные наблюдения.

Базу принимаем по контракту обмена аддона (`AuctionScanDB.exchange`, `marketExchange`):
форма `scans[]`, строки лота и `items`. `v` — внутренний формат базы для миграций аддона;
его смотрим, только пока `exchange` нет. Мотивация: аддон поднимает `v` при перестройке
своих разделов, которые клиент не читает, — проверка `v` ломала обмен без причины.

| База | Что делает Updater |
|---|---|
| `exchange` не больше `marketExchange` | принимает при любом `v` |
| `exchange` новее | сканы не отправляет: «база Market Based Auction новее клиента синхронизации — обновите клиент синхронизации» |
| `exchange` не целое число от 1 | сканы не отправляет: «неверный номер обмена» |
| нет `exchange`, `v` от 1 до 3 | принимает |
| нет `exchange`, `v` больше 3 | сканы не отправляет: «обновите клиент синхронизации» |
| незнакомые поля базы и скана | пропускает; поля скана уходят в `raw` |
| скан без `id`, `t` или с нестроковым лотом | пропускает этот скан, «отложено (повреждённые)» |

Отказ по базе (контракт, файл повреждён, не читается, дописывается, не выбран аккаунт)
останавливает только отправку: история скачивается и ставится, причина — в строке
«Сканы» красным и в итоге обмена «Сканы не отправлены: …». Образец базы со всеми
`scope` — `testdata/auctionscan/` (копия `tools/fixtures/` аддона): новое поле или `scope`
в аддоне приходит сюда вместе с образцом, и тест падает у нас, а не у игрока.

POST отправляет неподтверждённые сканы пачками: до 50 сканов, 6 МиБ JSON и 10000
названий предметов в пачке (лимиты сервера — 50 сканов, 16 МиБ, 10000 названий).
Скан больше пачки уходит отдельным запросом; больше 8 МиБ или 10000 названий — «отложено (слишком большие)».
Отправляются сканы с `scope` `market` (или без поля), `item` с `itemID`, `query`, `family`,
`disenchant`; полными помечаются только `market`, `item` и `family` без пропусков и обрезки.
Остальные (`gems` и незнакомые) откладываются: не отправляются и не отмечаются, строка
«Сканы» пишет «отложено N сканов (камни): сервер их пока не принимает». Мотивация: сервер
отвергает всю пачку при незнакомом `scope`; отложенный скан уйдёт, когда его поддержат
сервер и `marketSendable`.
Все запросы обмена идут через один HTTP-клиент с keep-alive: TLS-соединение через
KeenDNS устанавливается один раз, а не на каждый запрос. Отметки отправки
сохраняются после каждой пачки; окно показывает «Отправляю сканы: N из M».
sourceID берётся из capabilities, исходный scanID сохраняется. Каждый скан содержит
полный raw-объект, охват, UTC since/observedAt, строки лотов и справочник затронутых
предметов. Времени не добавляются часы региона.
Сервер проверяет полноту и будущие даты. Ответ inserted/duplicate записывает локальный
ACK только для подтверждённого sourceID+scanID. Ошибка/обрыв или скан пачки без
подтверждения — ACK не появляется, обмен останавливается с ошибкой, следующая попытка
повторяет неподтверждённое. Локальный хеш замечает изменения ранее отправленного
содержимого; конфликт 409 не затирает наблюдение в БД.

Источник входа привязан к установке Updater и выбранному аккаунту: смена аккаунта
очищает вход и требует авторизации; источник будет другим, коллизий scanID между
аккаунтами нет. Статические серверные токены по-прежнему поддерживаются для импорта.
Адрес сервиса задаётся владельцем, не вшивается в публичный exe.

История скачивается страницами snapshot по явному рынку и периоду и копится в
`AuctionMarket-history.json`. После обхода сохраняется последний курсор: следующий
обмен просит только наблюдения, принятые сервером позже, и склеивает их с кешем по
sourceID+scanID+itemID (повтор заменяет запись). Наблюдения старше периода
выбрасываются. Полный обход заново — при смене адреса, источника, рынка или периода,
раз в сутки и если сервер отверг сохранённый курсор. Повтор курсора внутри одного
обхода считается ошибкой. Ограничение — 100000 наблюдений, ответ страницы
4 МиБ, отправка одного скана 8 МиБ. Слишком большие сканы не удаляются и требуют
отдельного серверного импорта; chunk-upload в этой версии отсутствует.

Updater сериализует проверенные JSON-поля в литеральный инбокс v1: `{v=1,version=…,
market={…},localSourceID=…,observations={…}}`. Формат — контракт с аддоном, описан в его
`docs/spec.md` («Общие наблюдения от Updater»). `version` — sha256 рынка и наблюдений файла
или набора частей. Мотивация своей версии у срезанного `data/shared.lua`: с общей аддон
счёл бы полный инбокс уже влитым и потерял бы старые наблюдения. Неполные, будущие и недостоверные по часам точки не включаются.

| Файл | Что | Куда |
|---|---|---|
| `%APPDATA%/ManaCode/AuctionMarket-inbox.lua` | то же, что `data/shared.lua` | всегда, служебная копия |
| `AddOns/ManaCode_AuctionScan_Shared/ManaCode_AuctionScan_Shared.toc` | `LoadOnDemand: 1`, `X-ManaCode-Inbox: 1`, файлы данных по порядку | релиз и папка разработки |
| `AddOns/ManaCode_AuctionScan_Shared/inbox.lua` | глобальная `ManaCodeAuctionScanInbox`, первые 40 000 наблюдений | релиз и папка разработки |
| `…/inbox_2.lua`, `inbox_3.lua`… | `inbox.parts[#inbox.parts + 1] = {…}`, следующие по 40 000; лишние от прошлой выгрузки удаляются | когда наблюдений больше 40 000 |
| `ManaCode_AuctionScan/data/shared.lua` | `ns.SharedInbox`, последние 40 000 наблюдений; срезан — своя `version` | только не в папке разработки: для версий аддона без инбокса |

Аддон-инбоксом владеет Updater, в репозитории аддона его нет, поэтому история ставится
и в папку разработки (рядом `.git`, в том числе за junction). `data/shared.lua` в папке
разработки не пишется: в репозитории это отслеживаемая заготовка, история попала бы в
коммит и релиз. Предел 40 000 наблюдений на файл — бюджет констант одного куска Lua 5.1.

Совпадают все файлы — ничего не пишется. Пока игра работает — установка отложена,
статус помечает её ожидающей. После закрытия Wow.exe и получения общего install-lock
файлы записываются атомарно; новый файл в `.toc` клиент видит только после полного
перезапуска, `/reload` не хватит. Каждая запись и каждое переименование заново проверяет
игру; после последнего старта Wow.exe выдерживаются две минуты, `.toc` меняется последним.
SavedVariables снаружи не редактируются. Обновление
аддона сохраняет установленный `data/shared.lua` даже при наличии пустого шаблона в архиве.

| Обмен запускается | Отправка сканов | Догрузка истории |
|---|---|---|
| Автообмен, каждые 2 мин (`marketPullEvery`) | только если SavedVariables изменился | да |
| Автообмен, SavedVariables изменился (после `/reload`), не раньше минуты после прошлой попытки | да | да |
| Отложенная установка и игра закрыта — не раньше 30 с, даже при выключенном автообмене | если файл изменился | да |
| «Синхронизировать сейчас», вход, `-market` | да | да |

SavedVariables читается и разбирается только для отправки, при закрытых клиентах и через
60 секунд после последнего наблюдавшегося выхода. При старте Updater без истории
процессов тоже выдерживается минута. Файл открывается через Win32 CreateFile с
FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE и закрывается сразу после чтения.
Ожидание этого срока не помечает базу обработанной: следующая попытка повторит отправку.
Пустая фракция в
настройках тоже требует отправки: фракция берётся из сканов. Метка файла фиксируется
на старте обмена: запись нового скана во время запроса не теряется. Обмен защищён
от двух одновременных процессов отдельным named mutex; второй процесс молча
пропускает ход. Окно и обмен меняют `AuctionMarket.json` и статус под замком `AuctionMarket.lock`, перечитывая файл: обмен пишет только done, sources и пустую faction. Ошибки и обмены с новыми данными пишутся в `updater.log` с
префиксом «рынок:». `-market` запускает тот же конвейер из командной строки с
сохранёнными настройками; код 1 — обмен не завершён или сканы не отправлены.
Отказ по базе тоже ставит метку файла: повтор — когда SavedVariables изменится.

Графики показывают наблюдения цены и предложения. Исчезновение лотов не подтверждает
продажу; расчёт сопоставимых диффов выполняет сервер по полным непересекающимся снимкам.
